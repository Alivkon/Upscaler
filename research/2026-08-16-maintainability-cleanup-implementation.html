Витрина: файл-индекс

Порядок карточек задавался временем изменения файла, а git ставит всем файлам время выгрузки — у всех десяти стартовых карточек оно совпадало до миллисекунд. Теперь порядок записан явно в images/gallery.json: чтобы закрепить работу первой, достаточно передвинуть строку. Файлы больше не копируются — запись ссылается на существующий файл, а не создаёт вторую и третью копию. Пул раздаётся отдельным маршрутом /images/storage, из-за чего INTERNAL_IMAGE_STORAGE_DIR наконец работает без копирования внутрь проекта.

После этого server.js дошёл до 391 строки, и работа с изображениями выделена в gallery.js (168 строк); server.js вернулся к 253 и остался про HTTP и Replicate.

Проверено на живом сервере, до и после выделения одинаково: перенос сохраняет порядок; продвижение добавляет запись и не копирует файл; повторной выдачи уже показанного исходника нет; публикация не создаёт копию и не даёт дубля; пять одновременных refresh — 18 → 23 записи, дубликатов 0; записи с обходом каталога и ссылкой на удалённый файл пропускаются; внешний пул отдаётся с HTTP 200.

Ключевые решения

  • Форматирование — отдельным коммитом, его SHA в .git-blame-ignore-revs, чтобы git blame показывал настоящего автора.
  • Команда проверки называется verify: yarn check — встроенная команда yarn 1, она перекрыла бы скрипт и завершилась успешно, ничего не проверив.
  • Введён HttpError: наружу уходит только текст, написанный для посетителя, остальное — в лог.
  • Изображения не хранятся в git; каталоги остаются через .gitkeep, фотографии живут на сервере.

Что изменилось в поведении

  1. Ссылка на результат: /outputs/… → /images/generated/… (тот же каталог под одним именем).
  2. Посетитель больше не видит «Добавьте действительный REPLICATE_API_TOKEN в файл .env» — это сообщение уходит в лог.

Отдельно: после свежего git clone коллекция пуста, пока фотографии не положены в images/storage на сервере. Это не ошибка.

Проверки

yarn verify — код 0. Маршруты на живом сервере: /api/gallery 200, /api/upscale без файла 400, share/x.txt 400, share/no.jpg 404, отсутствующий файл 404, удалённый /outputs/… 404. Утечка токена проверена запросом с картинкой: в ответе «Внутренняя ошибка сервера», сообщение о токене — в логе.

Форматирование не изменило вёрстку: страница отрисована до и после, совпали innerText и прямоугольники всех 94 элементов в обоих режимах. В браузере проверены лайтбокс, метка кнопки во всех переходах размеров и возврат window.open/close/status браузеру.

Ограничения

Реальные вызовы Replicate не выполнялись — они платные, поэтому успешный путь /api/upscale проверен только до места, где нужен токен. .git по-прежнему 68 МБ: снятие с учёта не удаляет объекты из истории, а перезапись истории ломает существующие клоны — это решение владельца репозитория.
