## 2. Главное: где что живёт

Граница проведена по вопросу, на который отвечает половина.

| | отвечает на | что там |
|---|---|---|
| **wallpaper-gen** | *как работа сделана* | палитра, свет, композиция, размеры, зерно, **имя файла** |
| **Upscaler** | *что о работе сказано* | `ref`, `slug`, `title`, `alt`, `tags`, `added`, лицензия, происхождение |
| **`images/manifest.json`** | *что получилось* | какие файлы есть и какого они размера |

Соединяются по **`ref`**.

### Правило, которое держит всю конструкцию

**Сайт не складывает имён файлов и не измеряет картинки.** Он читает готовое
из манифеста.

Складывал бы — правило имён жило бы в двух репозиториях и однажды разошлось
бы; страница сослалась бы на файл, которого нет. Измерял бы — заявил бы
размер, которого у файла нет: работа не всегда выходит запрошенного размера,
музейный скан кончается там, где кончается скан музея.

Если в `gallery.js` или `pages.js` снова появится вычисление имени файла —
это откат к тому, из-за чего разделение и делалось.

### Форма манифеста

```json
[{ "ref": "vl-0001",
   "file": "plates/dusk-ridge-…-1440x3120.jpg", "width": 1440, "height": 3120, "bytes": 1061841,
   "preview": { "file": "plates/…-720x1560.jpg", "width": 720, "height": 1560 },
   "before":  { "file": "before/….jpg", "width": 347, "height": 752, "bytes": 3046 } }]
```

Пути — от корня `images/`, той же формы, что записи `images/gallery.json`.

## 3. Решения, которые нельзя переоткрывать молча

- **Одна картинка — одна работа — одна страница.** Кадров нет. Телефонная
  и экранная версии — две записи (`vl-0001`…`0012` и `vl-0013`…`0024`).
  Причина музейная: 16:9 и 9:19,5 не могут оба сохранить половину холста,
  у картины кадр ровно один. Решение Charlie, дословно: «one image per
  image page».
- **Порядок на указателе — кураторский**, порядок массива в `works.js`.
  Не по дате. Отдельно выбран Charlie при живом предложении newest-first.
- **`slug` не меняется после публикации** и живёт **в Upscaler**: адрес
  страницы — дело сайта. Имя файла — дело генератора, совпадение слов удобно,
  но необязательно.
- **Показывается копия, отдаётся работа.** В `srcset` только копия; полный
  файл — в `src`, в `contentUrl`, в карте сайта, под «Download» и в лайтбоксе.
  Копия не объявлена нигде. Указатель: 10 578 691 -> 556 378 B.
- **У опубликованной работы файл не меняется.** Картинки отдаются с годовым
  кэшем и `immutable`, правка настроек рендера до вышедшей работы не дойдёт.
  Новые настройки — для новых работ.
- **Пул `images/storage` в коллекцию не попадает** (Depositphotos, Adobe Stock).
- **Публикация чужих загрузок закрыта в двух местах:** галочка `disabled`
  и маршрут `/api/gallery/share`, отвечающий 403.
- **Своя лицензия, не CC0** (`/license`).
- **Картинки и манифест путешествуют не через git.** `images/` в `.gitignore`
  целиком. Решение Charlie: «we will have a bunch of other images this is fine,
  they'll travel separately».

## 5. Что дальше

### 5.1. Каталог из JavaScript в JSON

Решено Charlie с сессией `upscaler-0d`: «yeah json sounds good, any order is
fine for this mvp, whatever's simplest». **Ещё не начато.**

Форма согласована с ней:

- обязательные поля: `ref`, `slug`, `title`, `alt`, `added`;
- необязательные: `tags`, `license`, происхождение (музей, инвентарный номер,
  автор, дата, адрес страницы музея, адрес исходника);
- один файл на работу — снимает столкновения при одновременной правке;
- проверка схемы вместо `node --check works.js`, **включая уникальность
  `slug`**;
- порядок на указателе задаётся явно, иначе будет порядок файловой системы,
  а это расходится с кураторским.

Текстовая половина стала вдвое меньше и **форму больше не поменяет** —
`upscaler-0d` ждёт сигнала, что можно переносить. Сигнал можно давать.

Делать это должна одна сессия. У `upscaler-0d` готовы **121 музейная работа**
(Cleveland, CC0): 65 телефонных, 56 экранных, лежат вне репозитория.

### 5.2. Посмотреть указатель глазами

Указатель теперь смешивает вертикальные и горизонтальные работы. Они выровнены
по средней линии — решение сознательное, записано в `styles.css`: картины
вешают по общей средней линии, а не по общему верху. На одинаковых телефонных
работах это было не видно, теперь видно, и ряды получаются с провалами.
Довод остаётся верным или нет — решать глазами, не рассуждением.

## 7. Локальное окружение

**`.env` содержит рабочий `REPLICATE_API_TOKEN`.** Каждый вызов `/api/upscale`
стоит денег. За сессию не сделано ни одного вызова; **валидность токена
у Replicate так и не подтверждена.**

**Перезапуск сервера.** `pkill -f 'node server.js'` ловит сам себя и убивает
шелл. По слушающему порту:

```sh
pid=$(ss -lptnH "sport = :3000" | grep -o 'pid=[0-9]*' | head -1 | cut -d= -f2)
[ -n "$pid" ] && kill "$pid"
nohup node server.js > /tmp/server.log 2>&1 &
```

**Свежая копия.** Картинок в git нет. Чтобы коллекция была непустой:

```sh
cd ../wallpaper-gen && yarn install && node render.mjs   # пишет в ../Upscaler/images
```

Сейчас на диске: 48 файлов в `images/plates`, 24 в `images/before`,
24 записи в манифесте.

**Проверка рендера.** Он детерминирован, поэтому правка, которая не должна
была тронуть картинки, проверяется сверкой `md5sum` до и после. Так проверен
перенос: 60 файлов из 60 совпали.
