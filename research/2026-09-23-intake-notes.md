# Записи приёмки: что случилось в браузере

23.09.2026.

## Повод

Первые увеличения с чужих машин. Журнал за 13–23.09:

| когда (UTC) | visit | откуда | что |
|---|---|---|---|
| 21.09 12:46 | 4b3763fa | reddit → `/` → `/restore` | `/api/upscale` 200, 64.7 с, ответ 306 КБ |
| 21.09 13:18–13:30 | 4b3763fa | `/restore` ×3 | файл принесён, отделка в превью, на сервер ничего |
| 21.09 20:27 | 66d22cd6 | `/restore` без реферера | то же, на сервер ничего |
| 23.09 13:31 | 84b91a8f | `/restore` без реферера | `/api/upscale` 200, 86.3 с, ответ 955 КБ |
| 23.09 13:34, 13:37 | 84b91a8f | `/restore` ×2 | файл принесён, на сервер ничего |

Все три `visit` — Windows, Chrome 153, США, en-US. Людей из США в эти дни
4–6 в сутки. Скорее всего один человек, но это не доказано: Chrome 153 на
Windows — самый частый браузер, а заход на `/restore` без реферера за 10 дней
был 7 раз.

Чего по журналу узнать было нельзя:

- размер принесённой картинки — строка `upscale: …` пишется только в консоль
  контейнера, и выкладка 23.09 в 18:44 её стёрла;
- что было после пяти поздних заходов: отделка без увеличения считается
  в браузере, скачивание берёт blob из памяти, правая кнопка — тоже без
  запроса. «Сделал обои у себя», «сохранил превью» и «ушёл» в журнале
  выглядят одинаково.

Картинки сервер не хранит (`multer.memoryStorage`, ответ — байтами), поэтому
повторить их увеличение самим нельзя.

## Решение

Приёмка шлёт пустой `sendBeacon` на `/api/note/<событие>/<подробности>`.
Строку пишет существующий `journal.js`, новых столбцов и файлов нет.

| событие | подробности | где |
|---|---|---|
| `chose` | способ (`pick`, `drop`, `paste`), `ШxВ`, формат, вес в КБ | `bring` |
| `refused` | способ, формат (HEIC и прочее, что не берём) | `bring` |
| `made` | кто считал (`server`, `browser`, `webgpu`, `wasm`), галочки, `ШxВ` готового, секунды от нажатия | `showResult` |
| `failed` | `open`, `preview`, `finish`, `server`, `browser`, `show` | по одному на каждый `catch` |
| `download` | кто считал | кнопка Download |
| `rightclick` | `preview` или `made` | `contextmenu` на проёме |
| `left` | `preview` или `made` | `pagehide`, только если файл принесён |

Имя файла не отправляется: оно бывает личным, а журнал обещает, что личного
в нём нет. Сервер пропускает с кодом 204 только эти семь слов и до пяти
подробностей из `[a-z0-9.,-]`; всё остальное — 404, как любой чужой адрес.

## Файлы

- `public/note.js` — новый: отправка и довод, что отправляется и что нет;
- `public/intake.js` — вызовы `note` в семи местах, `bring` получил способ;
- `server.js` — маршрут `POST /api/note/…` → 204;
- `scripts/journal-rollup.mjs` — таблица «Приёмка (/api/note)».

## Ограничения

- `rightclick` — намёк: меню открыли, а «Save image as» могли не выбрать.
  Долгое нажатие на телефоне вызывает `contextmenu` не везде (iOS Safari — нет).
- `left` на телефонах теряется чаще: `pagehide` при сворачивании вкладки
  приходит не всегда.
- Блокировщик может резать `sendBeacon`; путь назван `note`, а не `track`
  или `collect`, но гарантии нет.
- Путь `server` проверен только curl'ом: живой вызов модели не делался.
- До выкладки ничего из этого на боевой машине не пишется.

## Правки после ревью (23.09, вечер)

Ревью нашло три дыры; все три закрыты.

- **Словарь, а не набор знаков.** Маршрут пропускал любой путь из
  `[a-z0-9.,-]`, то есть и `chose/passport-john.jpg`. Теперь 204 получает
  только путь из `NOTED` (`public/note.js`): по строке на событие, закрытые
  списки и числа. Формат файла тоже из списка (`formatOf`), чужой подтип —
  `other`. Сервер берёт словарь из того же файла, второго списка нет.
- **Потолок и чужие сайты.** `noteAllowance` в `limits.js`: 60 записей в час
  с адреса, сверх — 429. `Sec-Fetch-Site` не `same-origin` — 403. Сводка
  считает только 204, так что налитое в неё не попадает.
- **Сцена вместо «готово или нет».** `left` и `rightclick` пишут сцену на
  экране (`measured`, `offered`, `working`, `done`), её запоминает
  `setStage`. Прежнее `preview`/`made` путало ушедшего во время счёта с
  ушедшим до кнопки, а после отказа в новом файле писало `made` по старой
  работе — это видно и в проверке выше: `refused/paste/heic`, затем
  `left/made`.

Проверка — curl на тестовый сервер (порт 3055, журнал в scratchpad):

```
204  chose/pick/1200x1600/jpeg/15kb, made/server/crop,treat/2160x3840/86s,
     made/browser/none/1200x1600/1s, left/working, left/offered,
     refused/paste/heic, failed/open/other
404  chose/passport-john.jpg, refused/paste/passport-john, left/preview
403  Sec-Fetch-Site: cross-site, same-site
     60 подряд с одного адреса: 53 × 204 + 7 × 429 (с семью выше — ровно 60)
```

Страница в Chrome на том же сервере, увеличение снято (модель не звалась):
JPEG `passport John.jpg` 1200×1600 перетаскиванием, галочка dim, «Make my
wallpaper», правая кнопка на готовом, HEIC перетаскиванием, уход на `/license`:

```
api 204 /api/note/chose/drop/1200x1600/jpeg/14kb
api 204 /api/note/made/browser/treat/1200x1600/1s
api 204 /api/note/rightclick/done
api 204 /api/note/refused/drop/heic
api 204 /api/note/left/measured
```

Тот же путь, что утром дал `left/made`, теперь даёт `left/measured`.
Слова `passport` в журнале нет ни разу.

Что осталось как было: путь с 404 журнал пишет как любой ненайденный адрес,
на любом маршруте. Личного не шлёт наша страница; запретить это чужому
скрипту журнал не может.
