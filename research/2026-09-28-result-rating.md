# Оценка готового: «Rate the result»

## Цель

Узнать, нравится ли людям то, что вышло, и отдельно: нравится ли одинаково
то, что посчитал сервер, и то, что посчитал браузер. Download на это отвечает
плохо: часть людей сохраняет картинку правой кнопкой (это уже пишется как
`rightclick/done`), а скачанное ещё не значит понравившееся.

## Решения

- **Три ответа, один щелчок:** Poor · Fair · Good. После щелчка строка
  меняется на «Thank you.». Слово «Bad» не взято: звучит резко к посетителю,
  а не к картинке.
- **Строка видна сразу на готовом, а не после Download.** Иначе её не увидят
  те, кто сохраняет правой кнопкой.
- **Вид: «Rate the result: Poor · Fair · Good», ссылками, за чертой.** Первый
  вид, приглушённая строка, был невидим: Charlie не нашёл бы его, не зная,
  где искать. Второй, маленькие призрачные кнопки, был заметен, но терял
  лёгкость. Итог: цвет текста вместо приглушённого, своя строка за чертой,
  приглушённые точки между ответами и появление через секунду после готового
  (0.9 с, в скрытой вкладке ждёт, пока её откроют; при «меньше движения»
  не анимируется). Ответы переносятся одной группой.
- **Оценка уходит вместе с тем, кто считал:** `rated/<server|browser|webgpu|wasm>/<poor|fair|good>`.
  Ради этой пары её и спрашивают.
- **Без поля для слов.** Написанное посетителем может быть личным, а журнал
  обещает, что личного в нём нет.
- **Ни куки, ни нового маршрута.** Запись идёт тем же `note()` в тот же
  `/api/note`, сервер пускает только закрытый список.

## Изменения

- `pages.js`: `<p class="rating" id="intake-rating" hidden>` под `#intake-note`.
- `public/intake.js`: `GRADES`, `renderRating()`, вызов из `renderFinished`;
  `setStage` прячет строку вне сцены `done`.
- `public/styles.css`: `.rating`, `.rating__answers`, `.rating .link`, `.rating__dot`, `@keyframes rating-in`.
- `public/note.js`: в `NOTED` добавлено `rated/${MAKER}/(poor|fair|good)`.
- `scripts/journal-rollup.mjs`: таблица «Оценка готового», по паре
  «кто считал × ответ».

## Проверка

`yarn verify`: код 0 (синтаксис, форматирование, проверки журнала и счётчика).

Словарь `NOTED`:

```
ok  /api/note/rated/server/good
ok  /api/note/rated/browser/poor
ok  /api/note/rated/webgpu/fair
no  /api/note/rated/server/great
no  /api/note/rated/great
```

Сервер: `POST /api/note/rated/server/good` → 204, `…/rated/server/great` → 404.

В Chrome на `127.0.0.1:3000/restore`, без увеличения (модель не звалась,
`/api/upscale` в тесте ещё и перекрыт): до готового строка скрыта; на готовом
видна «Rate the result Poor Fair Good»; щелчок по «Good»
даёт «Thank you.» и строку в журнале `/api/note/rated/browser/good`;
«Do another» строку прячет. Сводка:

```
Оценка готового
  browser good  1
```

## Ограничения

- Ответов будет мало: одноразовые посетители, на такие строки обычно отвечают
  единицы процентов.
- Серверная ветка вживую не прогонялась (платный вызов); код у неё тот же,
  отличается только значение `provider`.
- Колонка 280 px проверена в Chrome: вопрос сверху, три ответа строкой под ним, без вылезания за край.
