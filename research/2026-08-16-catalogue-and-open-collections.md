# Каталог стал данными, коллекция — не только нашей

Дата: 16 августа 2026 · продолжает [записку о разделении
генератора](2026-08-16-generator-split.md)

Две задачи, сделанные вместе, потому что вторая упёрлась в первую: массив
в `works.js` не выдержал бы ста двадцати одной музейной работы, а десять
пришедших сегодня показали заодно, что сайт говорит о чужих работах как
о своих.

## 1. Каталог из JavaScript в JSON

Записи переехали в `catalogue/`: по файлу на работу, имя файла — её `ref`.

**Почему по файлу, а не одним массивом.** Над репозиторием работают
параллельно несколько сессий, и правка двух разных работ в одном файле —
это конфликт на ровном месте. Добавление работы теперь не трогает чужую
строку. Сегодня записей 34; из отобранных другой сессией их станет 155.

**Порядок задаётся `catalogue/order.json` и только им.** Порядок файловой
системы алфавитный, а коллекция — развеска, а не лента. Кураторский порядок
Charlie выбирал отдельно при живом предложении сортировать по дате.

**Каталог читается на каждом запросе, а не при загрузке модуля.** Шага сборки
в проекте нет намеренно, и публикация работы — это положить файл рядом
с картинкой, а не передеплоить сайт. Кэш свёл бы это обратно к перезапуску.

### Проверка вместо `node --check`

Записи стали данными, и синтаксис JavaScript о них больше ничего не говорит.
`scripts/verify-catalogue.mjs` проверяет то, что ломается молча:

| проверка | что было бы без неё |
|---|---|
| обязательные поля | опечатка `titel` не роняет сервер — страница выходит без заголовка |
| лишние поля | та же опечатка ловится с другой стороны |
| `ref` = имя файла | запись, которую не найдёт манифест |
| `order.json` = набор записей | работа есть, а на указателе её нет |
| формат `slug` и `added` | `16.08.2026` в `lastmod` карты сайта |
| **уникальность `slug`** | две страницы по одному адресу |
| лицензия заведена в `LICENSES` | `undefined` вместо условий в разметке |
| `provenance`: автор и адрес | работа без автора приписывается нам |

Дубликат `slug` — дороже всех: адрес после публикации не меняется, и найти
его, когда обе страницы уже в поиске, поздно.

Проверка проверена: в каталог внесены шесть поломок разом, найдены все шесть.

```
  vl-0004.json: запись есть, а в order.json её нет — работа не покажется
  order.json: vl-9999 висит в развеске, а записи vl-9999.json нет
  vl-0002.json: slug `dusk-ridge-dark-gradient-iphone-wallpaper` уже занят работой vl-0001
  vl-0003.json: поле `title` пусто или не строка
  vl-0003.json: лишнее поле `titel`
  vl-0003.json: `added` = "16.08.2026", а нужен ГГГГ-ММ-ДД

каталог: 6 проблем в 24 записях
```

## 2. Десять работ из открытых собраний

Одюбон (5), Геккель (2), Мериан (3). Отбирала сессия `upscaler-0d`
по контактным листам Commons; здесь — что с отобранным сделано.

Кроит их `wallpaper-gen/museum.mjs`. **Кадр выбирается правилом, а не рукой:**
крой публикуется, если сохраняет не меньше половины картины и не требует
растягивания. По этому правилу у работы кадр ровно один — вертикальная гравюра
идёт на телефон, горизонтальная на экран, панорамный свиток не идёт никуда
(из 132 отобранных в Кливленде так отсеялось 11). Скрипт отказывается печатать
работу, правилу не удовлетворяющую.

Посчитанное независимо двумя сессиями сошлось до процента:

```
vl-0025  5179×7940  -> 1440×3120   оставлено 71 %
vl-0026  4758×7781  -> 1440×3120   оставлено 75 %
vl-0027  8268×10136 -> 1440×3120   оставлено 57 %
vl-0028  5281×7743  -> 1440×3120   оставлено 68 %
vl-0029  5038×7844  -> 1440×3120   оставлено 72 %
vl-0030  2323×3280  -> 1440×3120   оставлено 65 %
vl-0031  2396×3363  -> 1440×3120   оставлено 65 %
vl-0032  2547×3500  -> 1440×3120   оставлено 63 %
vl-0033  5659×6996  -> 1440×3120   оставлено 57 %
vl-0034  3837×2649  -> 3837×2158   оставлено 81 %
```

**Ничего не увеличивается.** `vl-0034` не хватило трёх пикселей до 3840, и она
объявляет 3837×2158, а не 4K. То же будет со всеми кливлендскими: музей отдаёт
JPEG не длиннее 3400 px. Заявить 3840×2160 у файла в 3400 px значило бы соврать
разом в имени файла, в тексте страницы и в выдаче.

**Файла «до» у музейных работ нет.** У нарисованной он есть, потому что мы сами
её испортили и можем показать, из чего восстановили. Выдумать разрушенную
версию чужой гравюры и публично её «восстановить» — реклама под видом факта.

Крой ставится не по центру, а по «attention» sharp: Одюбон вешает птицу
к краю почти пустого листа, и центральный крой оставил бы бумагу без птицы.
Все десять кадров просмотрены глазами — сюжет уцелел везде.

## 3. Что пришлось починить из-за них

Две вещи, которые до сегодня были верны, потому что коллекция была только наша.

**Разметка приписывала гравюры нам.** `ImageObject` подставлял
`creator: Vellum` и `creditText: Vellum` каждой работе. На листе Мериан это
машиночитаемое присвоение чужого авторства — и читают его не глядя. Теперь
у работы с происхождением создатель — автор, `creditText` — держатель,
`isBasedOn` — адрес первоисточника. Крой авторства не создаёт: выбрать кадр
и уменьшить — действие механическое.

**Страница условий накрывала лицензией Vellum то, что нам не принадлежит.**
Она утверждала: «Every work in this collection is drawn by our own generator».
Появился раздел про открытые собрания — условий от нас там нет — и в нём
сказано, почему возраст сам по себе ничего не решает: гравюра 1705 года
свободна, а снимок этой гравюры бывает новым произведением с живым
правообладателем. Из 369 файлов контактного листа 40 отброшено именно
поэтому. Лицензии `public-domain` и `cc0` заведены раздельно: сказать «CC0»
про гравюру 1705 года неверно — её никто не выпускал под CC0.

Страница работы теперь называет автора, собрание и адрес, по которому
сказанное можно проверить, — иначе обещание из условий ничем не подкреплено.

## 4. Вторая ступень копии для показа

Гравюра при том же размере копии весит впятеро против градиента: на самой
тяжёлой, папоротниках Геккеля, копия 720 px дала 310 KB против 52 KB
у плашки. Указатель с музейными работами стал весить вдвое больше обычного.

Причина не в гравюрах, а в том, что ступень была одна. Карточка указателя
в 220 px просит 220 px при DPR 1 и 660 px при DPR 3, и одна ступень означает,
что кто-то из двоих переплачивает. `preview` в манифесте стал списком
`copies`, `srcset` предлагает 360 и 720.

Байты уже существующих файлов не тронуты — добавились только новые.

| страница | было, DPR 1 | стало, DPR 1 | DPR 3 |
|---|---|---|---|
| `/` | 556 378 B | **66 057 B** | 556 378 B |
| `/page/2` | 540 801 B | **60 645 B** | 540 801 B |
| `/page/3` (смешанная) | 1 020 306 B | **266 207 B** | 1 020 306 B |
| `/page/4` (музейная) | 662 549 B | **171 803 B** | 662 549 B |

Плотный экран получает столько же, сколько получал: ему крупная ступень
и нужна.

## Осталось открытым

- **`LEGAL.md` не тронут** — в нём чужая незакоммиченная правка. Ему нужны
  две строки: про авторство плашек и про то, что в коллекции теперь есть
  чужое, взятое по правилу «только Public domain, CC0 и No restrictions».
- **121 кливлендская работа** ждёт: у `upscaler-0d` есть и файлы (444 МБ),
  и тексты. Форма каталога под них готова, `museum.mjs` их скроит,
  но источник у них не Commons, а CDN музея — списку нужна ещё одна графа.
- **`No restrictions`** в `LICENSES` не заведён: работы с ним пока нет,
  а мёртвых записей не держим.
- **Указатель смешивает вертикальные и горизонтальные работы.** Теперь их
  видно рядом на четвёртой странице. Вопрос из прошлой записки остаётся
  открытым и решается глазами.
- **Домена по-прежнему нет.** Всё вышесказанное про поиск не работает,
  пока `SITE_ORIGIN` — `127.0.0.1`.
